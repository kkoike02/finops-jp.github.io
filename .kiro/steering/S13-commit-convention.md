# コミットメッセージ規約

## 目的
変更履歴の追跡性を確保し、CHANGELOGの自動生成を可能にする。

## ルール
Conventional Commits形式に従うこと。

## フォーマット

```
<type>(<scope>): <subject>

<body>

<footer>
```

### type（必須）
- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメントのみの変更
- `style`: コードの意味に影響しない変更（空白、フォーマット等）
- `refactor`: バグ修正でも新機能でもないコード変更
- `test`: テストの追加・修正
- `chore`: ビルドプロセスやツールの変更

### scope（推奨）
変更対象のコンポーネント名（例: `auth`, `blog`, `docs`, `framework`）

### subject（必須）
- 50文字以内
- 先頭小文字
- 末尾にピリオドを付けない
- 命令形（日本語の場合は「〜する」「〜を追加」）

### body（任意）
- 変更の動機と前後の違いを説明
- 72文字で折り返し

### footer（任意）
- 関連タスク番号: `Refs: TASK-015`
- 破壊的変更: `BREAKING CHANGE: [説明]`

### 例
```
feat(blog): 第4回ミートアップのブログ記事追加

- 記事本文とメタデータを追加
- 関連する画像アセットを配置

Refs: TASK-015
```
