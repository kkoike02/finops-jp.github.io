# 設計根拠の記録

## 目的
「なぜそうしたか」をレビュー時に説明可能にし、将来の保守・引き継ぎに備える。

## ルール
設計上の判断を行った場合、以下のフォーマットで設計根拠を必ず記録すること。
これは設計ドキュメント内の「設計根拠」セクション、またはコード変更時の
`docs/design-decisions.md` に記録する。

## フォーマット

```markdown
### DR-XXX: [判断タイトル]
- **日付**: YYYY-MM-DD
- **ステータス**: 提案 / 承認 / 却下 / 置き換え
- **コンテキスト**: [何が問題だったか、何を決める必要があったか]
- **決定**: [何を選んだか]
- **根拠**: [なぜその選択肢を選んだか]
- **代替案**:
  - [案A]: [却下理由]
  - [案B]: [却下理由]
- **影響**: [この決定の結果として何が変わるか]
```

## 適用タイミング
- 新規コンポーネントの追加
- 既存コンポーネントの構造変更
- ライブラリ/フレームワークの選定
- データモデルの変更
- APIインターフェースの変更
- パフォーマンスに影響する実装判断
