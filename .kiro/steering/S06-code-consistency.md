# 既存コードとの整合性

## 目的
機能追加時に既存アーキテクチャを壊さないことを保証する。

## ルール
コードを生成・修正する前に、以下を確認し従うこと：

### 命名規則
- 既存のファイル・ディレクトリ命名パターンに従う
- 既存のコンポーネント命名パターンに従う
- 新規名称は既存パターンから逸脱しない

### ディレクトリ構造
- 新規ファイルは既存の構造パターンに配置する
- 新規ディレクトリを作成する場合は設計根拠を記録する（S05参照）

### パターンの踏襲
- 既存コードで使われているデザインパターンに従う
- 既存のエラーハンドリングパターンに従う
- 既存のログ出力パターンに従う
- 新しいパターンを導入する場合は設計根拠を記録する（S05参照）

### import / 依存関係
- 既存のimport順序に従う
- 新規依存パッケージの追加は設計根拠を記録する
- 循環依存を作らない

### 確認手順
1. 変更対象ディレクトリの既存ファイルを読み取る
2. 命名・構造・パターンを把握する
3. 新規コードを既存パターンに合わせて生成する
4. 逸脱が必要な場合は設計根拠を記録する
