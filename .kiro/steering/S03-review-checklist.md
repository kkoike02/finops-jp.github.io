# レビュー観点チェックリスト

## 目的
AIが生成したドキュメントの末尾に、レビューアが確認すべき観点を自動付与する。

## ルール
aidlc-docs/ 配下のドキュメント（requirements.md, design.md, tasks.md）を生成・更新した際、
ドキュメント末尾に以下の「レビュー観点」セクションを必ず付加すること。

## テンプレート

### 要件ドキュメント用
```markdown
---
## レビュー観点チェックリスト
レビューアは以下の観点で確認してください：

- [ ] 要件の目的・背景が明確か
- [ ] ユーザーストーリーの粒度が適切か（大きすぎ/小さすぎないか）
- [ ] 受入条件が具体的で検証可能か
- [ ] スコープ外が明示されているか
- [ ] 既存機能への影響分析が妥当か
- [ ] 用語が用語集と一貫しているか
- [ ] 非機能要件の考慮漏れがないか
```

### 設計ドキュメント用
```markdown
---
## レビュー観点チェックリスト
レビューアは以下の観点で確認してください：

- [ ] 要件との整合性が取れているか
- [ ] 設計根拠（Why）が明記されているか
- [ ] 既存アーキテクチャとの整合性があるか
- [ ] 代替案が検討されているか
- [ ] エラーハンドリングが考慮されているか
- [ ] セキュリティ観点が考慮されているか
- [ ] パフォーマンスへの影響が考慮されているか
```

### タスク定義用
```markdown
---
## レビュー観点チェックリスト
レビューアは以下の観点で確認してください：

- [ ] 設計の全要素がタスク化されているか
- [ ] タスク粒度が適切か（1タスク=1PR程度）
- [ ] 依存関係が正しく定義されているか
- [ ] 完了条件が具体的で検証可能か
- [ ] テスト作成タスクが含まれているか
```
